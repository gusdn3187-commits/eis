# 규제 대응 모니터링 시스템

상장회사 경영기획 실무용. 법령·행정규칙의 제·개정을 감지하여 **우리 회사에 적용되는 의무와 이행 기한**을 자동으로 산출하고 규제대장을 갱신한다.

## 무엇을 하는가

```
① 감지    법제처 API + 금융위 RSS + 금감원/상장협     →  신규 규제 이벤트
② 판정    회사 규제 프로파일과 임계값 대조             →  적용 / 미적용 / 확인필요
③ 역산    시행일 + 유예 + 경과규정 → 사업연도 매핑     →  우리 기준 기한 + 착수시점
④ 산출    규제대장 갱신 + 보고자료 초안                →  임원 보고용
```

핵심 전제: **한국 상장사 규제 의무는 대부분 임계값 기반이다**(자산총액 2조 / 5천억 / 1천억, 시장구분, 사업연도). 따라서 적용 여부 판정은 판단이 아니라 계산이며, 자동화가 성립한다.

## 설치

1. 구글 드라이브에서 **새 스프레드시트** 생성 (예: `규제 대응 모니터링`)
2. 스프레드시트 상단 **확장 프로그램 → Apps Script**
3. 이 디렉터리의 `.gs` 파일을 각각 같은 이름으로 붙여넣기
4. 저장 후 스프레드시트를 새로고침하면 상단에 **[규제 모니터링]** 메뉴가 생긴다

## API 키 등록

`00_설정.gs` 의 `키_최초설정()` 함수에 값을 채우고 **한 번만** 실행한 뒤, **코드에서 값을 다시 지우고 저장**한다. 키는 스크립트 속성에 저장되며 코드에는 남지 않는다.

| 속성 | 발급처 | 소요 | 필수 |
|---|---|---|---|
| `DART_KEY` | opendart.fss.or.kr | 즉시 | ✅ |
| `LAW_OC` | open.law.go.kr | **승인 1~2일** | ✅ |
| `종목코드` | — | — | ✅ |
| `NAVER_CLIENT_ID` / `_SECRET` | developers.naver.com | 즉시 | 선택 |

### 법제처 신청 시 주의

- **서버 IP 칸은 비워둘 것.** Apps Script는 구글의 유동 IP에서 호출이 나가므로, IP를 지정하면 차단된다.
- **도메인은 "도메인 없음" 선택.**
- 분야는 전체선택하지 말고 필요한 것만: 현행법령 / 현행 행정규칙 / 법령·행정규칙 별표·서식 / 금융위원회 / 증권선물위원회 / 법제처 법령해석 (+ 공정거래위원회, 판례)
- 포맷은 JSON 중심. 단 **별표·서식은 본문이 HTML만 제공**된다.

## 실행 순서

| | 메뉴 | 하는 일 | 선행조건 |
|---|---|---|---|
| ① | 도달성 점검 | 구글 서버에서 각 소스에 닿는지 + 인코딩 확인 | 없음 |
| ② | 키 검증 | 등록한 키가 실제로 통하는지 확인 | 키 등록 |
| ③ | 회사 규제 프로파일 수집 | DART에서 자산총액·시장구분 등 자동 수집 | `DART_KEY`, `종목코드` |
| ④ | 규제 적용 판정 | 임계값 대조 → 규제대장 생성 | ③ 완료 + 수동 항목 입력 |

③ 실행 후 `회사프로파일` 시트에서 **[수동]** 표시 항목(지주회사 여부, 감사위원회 설치 여부, 이사 수 등)을 직접 채운 뒤 ④를 실행한다.

## ①번을 먼저 하는 이유

`도달성 점검`은 아키텍처를 결정한다. 상장협·금감원이 구글 IP를 차단하면 스크래핑 계층을 다른 곳(Cloudflare Workers, 국내 VPS 등)에 둬야 하고, 그러면 이후 설계가 달라진다. 코드를 더 쓰기 전에 확인한다.

인코딩도 함께 본다. 상장협 같은 구형 ASP 사이트는 EUC-KR인 경우가 많은데, Apps Script의 `getContentText()` 기본값은 UTF-8이라 그냥 쓰면 한글이 전부 깨진다.

## 시트 구조

| 시트 | 내용 |
|---|---|
| `점검결과` | 도달성 점검 이력 |
| `회사프로파일` | 임계값 판정의 입력값 (자동 + 수동) |
| `규제대장` | **본체.** 규제별 적용 여부·기한·조치·상태 |
| `감지로그` | 법령 개정 감지 이력 (04 구현 후) |

`규제대장`의 **상태** 열(준비전 / 진행중 / 완료)은 사용자가 직접 관리하며, 재실행해도 보존된다.

## ⚠️ 규제 판정을 자동 확정하지 말 것

`03_규제판정.gs` 의 규칙표는 **초안**이다. 각 항목에 `검증상태`가 붙어 있다.

- `✅ 확인됨` — 본 프로젝트에서 공식 자료로 근거를 확인한 항목
- `⚠️ 미검증` — **법제처 API로 조문 원문을 대조해야 하는 항목**

규제 오판은 비용이 비대칭적으로 크다. 이 시스템의 역할은 **놓치지 않게 하는 것**이지 판단을 대신하는 것이 아니다. 최종 확정은 반드시 사람이 조문을 보고 한다.
